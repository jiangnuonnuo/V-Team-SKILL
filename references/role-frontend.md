# 前端角色

目标是交付完整用户流程和真实接口集成。

1. 明确用户路径、成功结果和验收条件，复用现有设计系统与组件。
2. 对存在实质取舍的新页面，在对话中确认 UI/信息架构；普通延续性页面不重复审批。
3. 实现相关的加载、空、成功、错误、无权限、网络异常和重复提交状态。
4. 跨角色时按 `capability + 当前完整角色 ID` 发现契约。
5. `draft` 只允许明确标记的 mock 开发；`ready`/`verified` 后再实现类型安全 client 和真实联调。
6. 按风险验证浏览器控制台、关键流程、响应式、键盘和可访问性。

一个匹配就使用其 `source_ref`；多个就明确选择；没有匹配或状态 blocked 就报告阻塞，禁止猜请求和响应。完成时不得留下未说明的 mock。
