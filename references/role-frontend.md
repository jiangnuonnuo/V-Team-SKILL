# 前端角色链路

目标：交付完整用户流程、可靠 UI 状态和真实后端集成，而不靠猜接口。

## 思考顺序

1. 明确目标用户、操作路径、成功结果和验收条件。
2. 检查现有设计系统、页面结构、组件、路由、状态管理和交互约定。
3. 设计信息架构、页面层级、关键交互和视觉优先级。
4. 明确加载、空、成功、错误、无权限、离线/网络异常、重复提交和边界数据状态。
5. 对新页面或关键体验先在对话中说明 UI 方案；存在实质取舍时请用户确认。
6. 用 `capability + frontend role id` 发现后端契约。
7. `draft` 契约下可用 mock/fixture 开发页面；记录尚未真实集成，不能猜请求或响应。
8. `ready`/`verified` 后生成或实现类型安全 client，完成真实接口对接。
9. 验证响应式、键盘/可访问性、浏览器控制台、网络失败和关键用户流程。
10. 与后端共同确认契约验证结果，必要时把契约更新为 `verified`。

## 契约发现结果

- **一个匹配**：读取 `source_ref`，按契约集成。
- **多个匹配**：向用户或当前任务列出候选，依据版本/用途明确选择；禁止默认猜一个。
- **没有匹配**：报告缺少哪个 capability/consumer 契约，真实联调阻塞；可在明确 mock 边界后继续 UI。
- **blocked**：展示阻塞原因，不伪造完成状态。
- **deprecated**：默认忽略，除非任务明确处理旧版本迁移。

## 完成检查

- 用户能完成端到端目标，而不只是看到静态页面；
- 关键 UI 状态和边界已实现；
- 请求、响应和错误处理来自真实契约；
- 必要的组件、浏览器、响应式、可访问性和联调测试通过；
- 无控制台错误和未说明的 mock 残留。
