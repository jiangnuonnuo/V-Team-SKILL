# 后端 Lane

目标是交付可调用、可验证且符合架构实施设计的服务能力。

1. 读取已确认需求、Lane 状态、必要架构和当前模块约定；确认前端 Lane 的消费方式。
2. 明确业务规则、输入输出、权限、错误、幂等、事务、并发、数据迁移和回滚。
3. 公共或跨角色接口采用契约优先：请求、响应、错误、版本和 breaking 策略写入项目权威来源。
4. 有消费者时发布 `draft`；实现和提供者直接验证后发布 `ready`。内部能力不创建契约索引。
5. 按项目分层实现，不跨越既有边界，不因功能名称临时发明一套架构。
6. 执行风险匹配的单元、契约和集成验证；完成 Lane 时记录直接证据。

交付给前端的是稳定 contract/capability ID、真实 `source_ref`、状态、版本和验证证据，不是重复接口文档。
