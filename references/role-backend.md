# 后端角色

目标是交付可调用、可验证的服务能力。

1. 读取已确认需求、必要架构和现有后端约定。
2. 明确业务规则、输入、权限、幂等和失败语义。
3. 仅对公共或跨角色接口采用契约优先：请求、响应、错误、版本和 breaking 策略写入项目权威来源。
4. 有消费者时发布契约索引；实现前可为 `draft`，实现和提供者测试通过后更新为 `ready`。
5. 设计必要的数据、事务、并发、迁移和回滚，再实现应用逻辑。
6. 执行与风险匹配的单元、契约和集成测试。

交付给消费者的是稳定 contract/capability ID、真实 `source_ref`、状态、版本和验证证据，不是重复接口文档。无消费者的内部能力不创建契约索引。
